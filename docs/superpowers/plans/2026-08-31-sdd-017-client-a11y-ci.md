# SDD-017 Client Accessibility CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the client build and its WCAG accessibility smoke suite reproducible and mandatory in CI.

**Architecture:** Playwright starts the real Next.js client and exercises two stable, unauthenticated user seams: the landing page and login page. Axe scans their rendered DOM for WCAG 2.0/2.1 A and AA violations; GitHub Actions installs Chromium and runs the same public `pnpm test:a11y` command used locally.

**Tech Stack:** Next.js 16, pnpm 10.28.0, Playwright, `@axe-core/playwright`, GitHub Actions.

**Spec:** `docs/SDD-hardening-integridad-seguridad-operacion.md` (SDD-017, F-12)

## Global Constraints

- Keep the suite independent of the backend, seeded credentials, PostgreSQL, and Redis.
- Test behavior through browser-visible public routes, not component internals.
- Fail the gate for any automated WCAG 2.0/2.1 A or AA violation.
- Preserve the existing client lint, type-check, and production build gates.
